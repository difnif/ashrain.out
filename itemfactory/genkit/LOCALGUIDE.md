# 로컬 작업 지시 가이드 — 수치 변주가 조건과 어긋날 때 무엇을 어떻게 고치는가

이 문서 하나로 로컬에서 다음 일을 할 수 있다.
**시드를 돌려 문항을 만들고 · 탈락 통계를 읽고 · 시드를 고쳐 통과율을 올리고 · 고쳐도 안 되면
유형 자체를 바꿔 달라고 요청하기.** 새 유형을 처음부터 설계하는 일만 채팅 쪽 몫이다.

---

## 0. 한 문장 원칙

> **제약은 필터가 아니라 생성 규칙에 내장한다.**
> 값을 자유롭게 뽑고 조건에 어긋나면 버리는 방식은 타율이 바닥난다.
> 처음부터 조건을 만족하는 꼴로 값을 만들면 거의 다 통과한다.

이번 파일럿에서 이 원칙 하나로 바뀐 수치다.

| 틀 | 고치기 전 | 고친 뒤 |
|---|---|---|
| 소금물 혼합 (t1) | 6.2 % | 78 % |
| 수직선 중점 (t1) | 37 % | 86 % |
| 기울기 고르기 (t2) | 24 % | 69 % |
| **전체** | **통과 1,652 / 탈락 3,482 (32 %)** | **통과 1,798 / 탈락 895 (67 %)** |

문항 수는 늘고 낭비는 4분의 1로 줄었다. 시드 파일 몇 줄을 고친 것이 전부다.

## 1. 한 사이클

```bash
cd ashrain.out
pip install sympy --break-system-packages          # 최초 1회

# ① 생성 (DB 안 건드림)
cd itemfactory
python -m genkit.build seeds/*.json --n 120

# ② 어디서 얼마나 떨어졌나 → 무엇을 고쳐야 하나
python tools/diagnose.py --min 0.6

# ③ 시드를 고친다 (아래 §3 처방표)
#    seeds/<seed_id>.json 을 편집

# ④ 다시 ①~② 반복. 통과율이 60 % 를 넘고 공간이 목표의 3배 이상이면 충분하다.

# ⑤ 산출물 독립 감사 — 시드를 보지 않고 결과 JSON 만 재검사
python tools/audit.py out/gen

# ⑥ 눈으로 검수 — out/gen/review.html 을 브라우저로 연다
node tools/review.mjs --per 4

# ⑦ 승인 후에만 DB 반영
python -m genkit.build seeds/*.json --n 120 --push --status draft
```

`--push` 전에 `supabase/2026-09_item_gen_v2.sql` 이 적용돼 있어야 한다.

## 2. 리포트 읽는 법

`out/gen/<seed_id>_report.json` 과 콘솔에 이렇게 나온다.

```
m1-1-mixture-t1   공간 450 · 목표 100 · 통과 100 · 탈락 29
    ·  24건  G1:제약 위반 u != v
    ·   5건  G1:제약 위반 p <= 24
```

- **공간** = 파라미터 조합의 총수. 목표의 **3배 이상**이면 여유가 있는 것이다.
- **탈락**은 나쁜 게 아니다. 관문이 일하고 있다는 뜻이다. 문제는 **탈락이 많아서 목표를 못 채울 때**뿐이다.
- 관문 뜻: **G1** 성립 제약 · **G2** 독립 재풀이 · **G3** 오답지 · **G4** 문법·도형 · **G5** 형식·해설·라벨 ·
  **R-0x** 누적 검증 규칙 · **DUP** 중복.
- **G2·G4·G5 탈락이 있으면 시드에 실수가 있는 것**이다(수학이 틀렸거나 규격을 어겼다). 최우선으로 고친다.
- G1·G3 탈락은 대부분 "생성 규칙이 느슨해서" 생긴다 — §3 처방표.

## 3. 처방표 — 사유별로 시드를 어떻게 고치는가

`python tools/diagnose.py` 가 아래 진단을 자동으로 붙여 준다. 원문 예시와 함께 정리한다.

### ① `G1: 제약 위반 ... % ... == 0` — 정수해 조건을 사후에 걸러내고 있다

**나쁜 예 (부채꼴, 통과율 30 % 대)**

```json
"params": [{"name":"r","values":{"int":[2,24]}},
           {"name":"th","values":{"in":[30,45,60,90,120]}}],
"constraints": ["(2*r*th) % 360 == 0"]
```

**고친 것 — 조건을 대수로 풀어 생성 규칙에 넣는다**

360 이 2rθ 를 나누려면 r 이 `360/gcd(2θ,360)` 의 배수여야 한다. 그러니 r 을 직접 뽑지 말고
그 배수만 만든다.

```json
"params": [{"name":"th","values":{"in":[30,45,60,90,120]}},
           {"name":"k","values":{"int":[1,10]}}],
"derive": {"M":"360/gcd(2*th,360)", "r":"k*360/gcd(2*th,360)",
           "kl":"2*(k*360/gcd(2*th,360))*th/360"},
"constraints": ["r <= 36", "kl >= 2"]
```

**다른 예 (소금물 혼합, 6.2 % → 78 %)**
조건 `(p·x + q·y) % (x+y) == 0` 을 손으로 풀면, x=100u, y=100v, p=q+k 일 때 `(k·u) % (u+v) == 0`
이다. g=gcd(u,v), m=(u+v)/g 로 두고 **k 를 m 의 배수로 뽑으면** 언제나 성립한다.

```json
"params": [{"name":"q","values":{"in":[2,3,4,5,6,8]}},
           {"name":"u","values":{"int":[1,5]}},
           {"name":"v","values":{"int":[1,5]}},
           {"name":"j","values":{"int":[1,3]}}],
"derive": {"k":"((u+v)/gcd(u,v))*j", "p":"q + ((u+v)/gcd(u,v))*j",
           "x":"100*u", "y":"100*v", "c":"q + j*u/gcd(u,v)"}
```

### ② `G1: 제약 위반 a < b` 같은 순서·간격 조건

**나쁜 예** — a, b 를 따로 뽑고 `a < b`, `(a+b) % 2 == 0` 을 검사 (37 % 통과)
**고친 것** — 간격을 파라미터로 (86 % 통과)

```json
"params": [{"name":"a","values":{"int":[-12,10]}},
           {"name":"h","values":{"int":[1,11]}}],
"derive": {"b":"a + 2*h", "m":"a + h", "d":"2*h"}
```

`b = a + 2h` 로 만들면 `a < b` 와 짝수 합이 **자동으로** 보장된다.

### ③ 서로 얽힌 두 조건 (`n > d` 이면서 `n < 2d` 같은 것)

파라미터 하나에 **두 값을 인코딩**한다. 조합 목록을 직접 쓰면 된다.

```json
"params": [{"name":"rt","values":{"in":[23,34,35,45,47,56,57,58,59]}}],
"derive": {"dd":"floor(rt/10)", "nn":"rt % 10"}
```

`rt = 47` 이면 d=4, n=7. 유효한 조합만 목록에 넣었으므로 탈락이 없다.

### ④ `G1: 파생값 ... 계산 실패` — 퇴화 조합

`derive` 는 `constraints` 보다 **먼저** 계산된다. 0으로 나누거나 복소수가 되는 조합은
constraints 로 막을 수 없으니 **params 범위에서 빼야** 한다.
(삼각형 각도에서 `a + b >= 180` 인 조합이 대표적이다.)

### ⑤ `G3: R-01 겉모양 불일치` — 정답은 정수인데 오답이 분수

정답과 오답의 겉모양이 다르면 학생이 계산 없이 배제한다. 그래서 규칙이 자동으로 버린다.

- 오답 식을 정답과 같은 꼴로 만들거나,
- `distractor_fmt` 로 표기를 통일하거나(예: `"[[{v} * pi]]"`),
- 그 오개념을 포기하고 다른 오개념 오답을 쓴다.

`dx/dy`(기울기 뒤집기)처럼 **구조적으로 분수가 되는 오답**은 정답이 정수인 문항에서는 못 쓴다.
대신 `dx`(x의 증가량을 그대로 답으로) 같은 정수 오답으로 같은 오개념을 잡는다.

### ⑥ `G3: 쓸 수 있는 오답이 3개` — 오답 후보 부족

**distractors 를 6~8개 넣어라.** 4개만 두면 하나만 탈락해도 문항이 통째로 버려진다.
`R-02 값 붕괴`(퇴화 파라미터에서 서로 다른 오개념이 같은 값이 됨)는 자주 일어나므로 여유가 필요하다.

### ⑦ `DUP: 문면+보기 동일(도형만 다름)`

수치가 그림에만 있으면 발문이 서로 같아져 DB에서 병합된다. **발문에도 수치를 쓴다.**
`∠A = 40°, ∠B = 65°일 때` 처럼. 접근성·검색 면에서도 이쪽이 옳다.

### ⑧ `G3: R-05 정답이 문면에 노출`

특정 파라미터에서 답이 발문의 수와 같아지는 경우다(중심각 180°면 호의 길이 계수 = 반지름).
`constraints` 에 `kl != r`, `c != a` 처럼 그 조합만 빼면 된다.

## 4. 고쳐도 안 될 때 — 유형 자체를 바꾸는 판단

아래 **셋 중 하나라도** 해당하면 시드 손질이 아니라 **유형 재설계**가 필요하다.
이때는 아래 §5 양식으로 채팅에 요청한다.

1. **공간이 목표의 2배 미만**이다. (예: 다각형 내각의 합은 n = 5~12 라 공간이 8뿐이다.
   더 만들려면 변주축을 바꿔야 한다 — 내각의 합 → 한 내각 → 외각 → 대각선 개수처럼.)
2. **처방표 ①~③을 적용해도 통과율이 40 % 아래**다. 조건이 서로 얽혀 있어 생성 규칙으로 못 푸는 경우.
3. **G2 탈락이 계속 난다.** 관계식이 유일해를 주지 못한다는 뜻이고, 이건 수치가 아니라
   **문항의 조건 설계** 문제다. (조건이 부족하거나, 두 해가 다 말이 되거나.)

### 유형을 바꾼다는 것의 구체적 의미

같은 개념을 붙잡고 **변주축을 옮기는 것**이다. `schemas.axes` 가 그 목록이다.

| 막힌 축 | 옮겨 갈 축 |
|---|---|
| 구하는 값이 정수로 안 떨어진다 | 답을 π·분수 꼴로 그대로 두는 유형으로 (부채꼴·원) |
| 수치 조합이 너무 좁다 | 미지수 위치를 바꾼다 (l 미지 → r 미지 → θ 미지) |
| 그림이 조건과 어긋난다 | `scene` 으로 좌표를 직접 계산해 주는 형태로 |
| 조건이 서로 얽혀 유일해가 안 나온다 | 조건을 하나 더 주는 유형(연립)으로, 또는 선다형으로 |
| 공간이 근본적으로 작다 | 맥락(서사)을 변주축으로 추가 — 같은 수식에 다른 상황 |

## 5. 채팅에 재설계를 요청하는 양식

이대로 붙여 넣으면 바로 새 시드를 받을 수 있다.

```
[시드 재설계 요청]
시드: m1-2-sector-arc  /  틀: m1-2-sector-arc-t3
현재 통과율: 26/66 (39%) · 공간 66 (목표의 0.7배)
주요 탈락 사유:
  16건 G1:제약 위반 r <= 24
   8건 G3:쓸 수 있는 오답이 3개 (R-03 문면에 이미 나온 수)
시도한 처방: ①(생성 규칙 내장) 적용함, ⑥(오답 8개로 증설) 적용함
막힌 지점: r 이 M 의 배수라 값이 띄엄띄엄해서 공간이 안 늘어남
원하는 방향: 넓이 대신 '호의 길이와 넓이의 관계(S = l·r/2)'를 묻는 축으로 바꾸고 싶음
```

여기에 `out/gen/<seed_id>_report.json` 을 첨부하면 더 좋다.

## 6. 검수 규칙 — 반드시 경계를 본다

버그는 파라미터 공간의 **양끝에서** 조용히 생긴다(설계문서 v0.1 §4의 버그 ②③④가 전부 그랬다).
중앙 표본만 보면 못 잡는다.

- 라벨 `L23_param_bucket` 이 `경계` 인 문항을 **반드시** 검수 표본에 넣는다.
  `review.html` 의 카드 아래에 `경계구간`으로 표시된다.
- 표본은 틀마다 최소 **처음 · 중간 · 끝 3개**.
- 눈으로 볼 것: ⓐ 그림이 조건과 맞는가 ⓑ 답이 발문에 노출되지 않았는가
  ⓒ 오답 5개가 형식이 고르고 하나만 튀지 않는가 ⓓ 해설이 그 수치로 말이 되는가.
