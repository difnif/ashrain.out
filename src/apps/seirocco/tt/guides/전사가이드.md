# 전사 가이드 — 애쉬레인 강사도구 내보내기 {{BATCH}}

이 묶음은 학원 수업 프린트에서 뽑은 수학 문항입니다. **Gemini가 문항을 글로 옮기고(전사) 해설을 붙여 JSON으로 돌려주는 일**을 합니다.
결과는 선생님이 강사도구의 [전사 결과 가져오기]로 다시 넣고, 강사도구가 수식 문법(mathir)을 검사해 통과한 것만 쌓습니다.

- 문항 수: **{{N}}개** (문항+정답+해설 {{N_ALL}}개 · 해설만 {{N_SOL}}개) · 학교급: {{LEVELS}}
- 매쓰플랫 해설 그림이 함께 있는 문항: {{N_MFSOL}}개

> 이 자료는 내부 참고용입니다. 문항을 다른 곳에 공개하거나 서비스에 그대로 쓰지 않습니다. 이미지에 있는 그대로 옮기고, 지어내거나 고쳐 쓰지 않습니다.

## 0. 묶음에 든 파일

| 파일 | 내용 |
|---|---|
| `문항.pdf` | 한 쪽에 한 문항. 쪽 맨 위 회색 띠에 **문항 ID · 할 일 · 학교급 · 빠른정답 · 유형**이 적혀 있다. 아래에 문항 그림, (있으면) 빠른정답 그림, DB 문항 글, 매쓰플랫 해설 그림. |
| `목록.json` | 문항마다 같은 정보(id, task, level, quick_answer, db_item, files …). |
| `결과_양식.json` | **채워서 돌려줄 틀**. 문항마다 칸이 미리 만들어져 있다. |
| `mathir.py` | 수식 문법 검사기(파이썬, 표준 라이브러리만 씀). 코드 실행이 되면 4관문 검사에 쓴다. |
| `images/` | 문항·빠른정답·매쓰플랫 해설 그림 낱장(PDF와 같은 것). PDF가 잘 안 읽히면 이것을 본다. |

## 1. 일하는 순서 — 꼭 이 순서대로, 한 번에 10문항씩

1. **목록 확인**: `목록.json`을 읽고 문항 수와 할 일(task) 종류를 세어 한 줄로 보고한다. 이 가이드의 2~5장을 끝까지 읽는다.
2. **10문항씩 전사**: `문항.pdf`의 쪽 순서대로 10문항을 골라 `결과_양식.json`의 해당 칸을 채운다.
   - 문항 하나를 끝내면 다음 문항으로. 여러 문항을 섞어서 쓰지 않는다.
   - 그림이 흐리거나 잘려서 확신이 없으면 지어내지 말고 `review`에 사유를 적고 넘어간다(→ 6장).
3. **검사**: 방금 쓴 10문항을 6장의 점검표로 확인한다. 코드 실행이 되면 `mathir.py`로 4관문을 돌린다(→ 6장 예시 코드). 오류가 난 문항은 고치거나 `review`로 돌린다.
4. **다음 10문항**: 2~3단계를 끝까지 되풀이한다. 중간에 끊기면 마지막으로 끝낸 문항 ID를 적어 두고, 다음에는 그 뒤부터 한다.
5. **합치기·보고**: 모든 문항을 하나의 JSON 배열로 합쳐 `결과_{{BATCH}}.json`으로 돌려준다(JSON 밖 글 없이). 끝에 따로 "통과 n · review n" 한 줄만 보고한다.

## 2. 할 일(task) 두 가지

### A. `all` — 문항+정답+해설 (DB에 대조본이 없는 문항)
- 문항 그림을 보고 `final`(문항 글·보기·정답 등)을 채우고, `solution`(해설)도 쓴다.
- 정답은 빠른정답(띠에 적힌 것 또는 빠른정답 그림)과 반드시 맞춘다. 직접 풀어 본 답이 빠른정답과 다르면 다시 확인하고, 그래도 다르면 `review`에 "빠른정답과 다름: 내 풀이 = …"로 적는다.

### B. `solution` — 해설만 (DB에 문항이 이미 있는 문항)
- `final`은 쓰지 않는다(칸이 없다). PDF의 「DB 문항 글」이 있으면 그 문항에 대한 해설만 쓴다. 문항 글은 고치지 않는다.
- DB 문항 글과 그림이 다른 문항으로 보이면 해설을 쓰지 말고 `review`에 "DB 문항과 그림이 다름"이라고 적는다.

### 해설의 근거
- **매쓰플랫 해설 그림이 있으면**(`solution.source` = `"mathflat"`): 그 해설을 옮겨 적는다. 문장은 그대로 두되 수식만 mathir로 바꾼다. 빠진 단계가 있으면 한 줄로만 보탠다.
- **없으면**(`"written"`): 직접 풀어서 쓴다(→ 4장).

## 3. 문항 전사 규칙 (`final`) — mathir 문법

### 3.1 수식 표기 (닫힌 문법 — 목록 밖 기호·함수 금지)
- 문장 속 수식은 `[[ ... ]]`로 감싸고, 그 안은 mathir만 쓴다. 단순한 수와 단위(`3 cm`, `25명`)는 마커 없이 평문.
- 유니코드 수식 문자(½, √, ×, ÷, ≤, ², π)와 LaTeX(`\frac`)는 **쓰지 않는다**. 대신:
  - 연산: `+ - * / =` `!=` `< > <= >=`, 괄호, 붙여 쓴 곱(`2x`, `3(x+1)`)
  - 분수 `frac(1,2)` · 대분수 `mixed(2,1,3)`(= 2와 3분의 1) · 거듭제곱 `pow(x,2)` · 제곱근 `sqrt(2)` · 절댓값 `abs(-3)`
  - 순환소수 `recdec(0.2,45)` · 각도 `deg(36)` · 백분율 `pct(20)` · 비 `ratio(2,3)` · ± `pm(3)`
  - 기하: `seg(AB)` 선분, `line(AB)` 직선, `ray(AB)` 반직선, `arc(AB)` 호, `angle(ABC)` 각, `tri(ABC)` 삼각형, `quad(ABCD)` 사각형,
    `par(seg(AB), seg(CD))` 평행, `perp(…)` 수직, `cong(…)` 합동, `sim(…)` 닮음, `point(3,-2)` 좌표
  - 집합·명제(고등): `set(1,2,3)` `in(a, A)` `union(A,B)` `inter(A,B)` `comp(A)` …
  - 경우의 수·확률: `perm(5,2)` `comb(5,2)` `fact(5)` `prob(A)`
  - 그 밖(고등): `log` `ln` `sin` `cos` `tan` `sub(a,n)` `sum(k,1,n,식)` `lim` `prime` `integ` `dinteg` `cases(식1, 조건1, 식2, 조건2)` `app(prime(f), x)`
  - 빈칸 □ (가)(나): `box(1)`, `box(2)` … · 약속 기호 ◎: `op(dcirc, a, b)` · 상수 `pi` `e` `inf` `cdots`
- 예: `[[frac(1,2) + frac(1,3)]]을 계산하면?` · `일차함수 [[y = 2x - 3]]의 그래프` · `[[angle(ABC) = deg(40)]]` · `[[mixed(3,1,4) * 4]]`

### 3.2 칸별 규칙
| 칸 | 규칙 |
|---|---|
| `qtype` | 보기 ①~⑤가 있으면 `choice`, 답만 쓰면 `short`, 서술을 요구하면 `essay` |
| `question` | 발문 전체(조건 (가)(나), 표의 내용, <보기> 포함). 줄바꿈은 `\n`. 원문 그대로(오탈자 포함). 번호·배점([3점])·머리말은 뺀다. |
| `choices` | `choice`일 때 보기 내용 5개(①~⑤ 기호는 빼고) 배열, 아니면 `null` |
| `answer` | 마커 없이 하나: 객관식은 `③`처럼 원문자, 그 밖은 `x = 8` · `frac(3,4)` · `15 cm` · `deg(36)` · `소수`(낱말). 여러 답은 `x = 1 또는 x = 2`, 함께 성립은 `a = 5, b = -1` |
| `difficulty_est` | 1(쉬움)~5(어려움) |
| `has_math` / `has_figure` | 정직하게 true/false |
| `figure` | 그림이 있으면 배열. 도형을 정확히 옮길 자신이 없으면 `[{"fn":"unsupported","args":{"raw":"그림 설명 한두 문장"}}]` |
| `unit_id` | 중학교 `m1-1`(중1 1학기)~`m3-2`, 고등학교 `h1-1`~`h3-3`, **초등학교 `e4-1`(초4 1학기)처럼 e+학년-학기**. 띠의 학교급과 내용으로 정한다. |
| `concept_main` / `concept_subs` / `pattern_tags` | 모르면 `null` / `[]` / `[]` 그대로 둔다 |
| `confidence` | 기본 0.9, 흔들리면 낮춘다. 0.7 아래면 `review`로 |

### 3.3 금지 세 가지
1. 이미지에 없는 것을 만들어 넣지 않는다(보기·수치·조건 창작 금지).
2. 검사(6장)를 통과하지 못한 것을 그냥 넣지 않는다 — 고치거나 `review`로. **틀리는 것보다 비워 두는 것이 낫다.**
3. mathir 목록에 없는 함수·기호를 새로 만들지 않는다. 표현할 수 없으면 `review`에 사유를 적는다.

## 4. 해설 규칙 (`solution`)

```json
"solution": {"outline": "한 줄 방침", "steps": ["1단계 문장", "2단계 문장", "..."], "check": "검산 한 줄", "source": "mathflat 또는 written"}
```
- 문장 속 수식은 3장과 같은 `[[ ]]` mathir 표기.
- 단계: **도형(기하) 문제는 2단**(① 도형 읽기 → ② 계산·결론), **그 밖은 3단**(① 방침 → ② 전개 → ③ 확인). 한 단계 안에서 문장을 여러 개 써도 된다.
- 서술형 답안의 풀이 과정으로 그대로 써도 될 만큼 자세히: 무엇을 x로 놓는지, 어떤 성질·공식을 쓰는지 이름을 밝힌다.
- 학년을 넘는 개념을 쓰지 않는다. **중2 문제·해설에는 제곱근(√, sqrt)을 쓰지 않는다**(피타고라스 수로 풀린다).
- **초등 문항**: 초등 교과서 말로 쓴다. 문자(x, y)로 식을 세우지 않고 □나 말로 설명한다. 짧은 문장, 쉬운 말. 분수는 `frac`, 대분수는 `mixed`.
- `check`: 답을 문제 조건에 다시 넣어 맞는지 한 줄로(예: "[[3 * 4 = 12]]이므로 조건에 맞다").

## 5. 결과 형식 — JSON 배열 하나만

`결과_양식.json`과 같은 모양으로, 문항마다 한 덩어리:

```json
[
  {"id": "8ACWPD-007", "task": "all", "review": null,
   "final": {"qtype": "choice", "question": "다음 중 [[frac(1,2) + frac(1,3)]]의 값은?", "choices": ["frac(1,6)", "frac(2,5)", "frac(5,6)", "1", "frac(7,6)"],
             "answer": "③", "difficulty_est": 2, "has_math": true, "has_figure": false, "figure": null,
             "unit_id": "e5-1", "concept_main": null, "concept_subs": [], "pattern_tags": [], "confidence": 0.9},
   "solution": {"outline": "분모를 같게 만들어 더한다.", "steps": ["두 분모 2와 3의 최소공배수는 6이다.", "[[frac(1,2) = frac(3,6)]], [[frac(1,3) = frac(2,6)]]이다.", "[[frac(3,6) + frac(2,6) = frac(5,6)]]이므로 답은 ③이다."], "check": "[[frac(5,6) - frac(1,3) = frac(1,2)]]이므로 맞다.", "source": "written"}},
  {"id": "8ACWPD-012", "task": "solution", "review": null,
   "solution": {"outline": "...", "steps": ["..."], "check": "...", "source": "mathflat"}},
  {"id": "8ACWPD-015", "task": "all", "review": "그림의 아래쪽이 잘려 보기 ⑤를 읽을 수 없음"}
]
```
- `id`·`corpus_id`는 바꾸지 않는다. `review`에 사유를 적은 문항은 `final`·`solution`을 비워도 된다.
- 문자열 안의 큰따옴표는 `\"`, 백슬래시는 `\\`로.

## 6. 점검표 (10문항마다)

- [ ] `id`·`task`가 양식 그대로인가
- [ ] 정답이 빠른정답과 같은가(객관식 번호, 단위 포함)
- [ ] 수식이 모두 `[[ ]]` 안에 있고, √ ½ × ÷ ² π 같은 문자를 쓰지 않았는가
- [ ] `choices`는 객관식일 때만, 5개(또는 문항에 적힌 개수)인가
- [ ] 해설 단계 수(기하 2 / 그 밖 3)와 학년 범위를 지켰는가
- [ ] 코드 실행이 되면 아래 4관문을 돌려 오류가 0인가

```python
import json, mathir
rows = json.load(open("결과.json", encoding="utf-8"))
for r in rows:
    f, s = r.get("final"), r.get("solution")
    errs = []
    if f:
        errs += mathir.parse_text(f["question"])[2]                    # ① 발문
        for c in f.get("choices") or []: errs += mathir.parse_text(str(c))[2]   # ② 보기
        if f.get("answer"): mathir.parse_answer(str(f["answer"]))        # ③ 정답 (예외가 나면 오류)
        if f.get("figure"): errs += mathir.check_figure(f["figure"])     # ④ 그림
    if s:
        for t in [s.get("outline", "")] + s.get("steps", []) + [s.get("check", "")]: errs += mathir.parse_text(str(t))[2]
    if errs: print(r["id"], errs[:2])
```
