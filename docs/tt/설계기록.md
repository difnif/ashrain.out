# 강사도구 설계 기록

강사도구의 기능마다 **선생님이 어떤 고민으로 요청했는지**, 무엇을 기본값으로 정했는지, 아직 정하지 않은 것이 무엇인지 적어 둔다.
「물어볼 것」(선생님께 묻는 기능)을 만들 때, 스캔본을 분석할 때, 새 기능을 덧붙일 때 이 문서를 기준으로 삼는다.

- 저장소가 공개이므로 학생 이름 · 프린트 내용은 적지 않는다.
- 요청은 날짜와 함께 요지만 옮긴다. 「기본값」은 Claude가 정한 것이라 선생님이 바꿀 수 있다.

## 지키는 원칙

- **화면이 돌 때는 AI를 부르지 않는다.** 분석 · 채점 판단은 채팅에서 Claude가 하고, 앱은 기록 · 내보내기 · 가져오기만 한다.
- **모르면 쓰지 않는다.** 애매한 판단은 기록하지 않고 「확인할 것」으로 남겨 선생님이 고르게 한다.
- **입력은 모두 업무 기록에 남기고 되돌릴 수 있게 한다.** 실수로 「입력 완료」를 눌러도 고칠 수 있어야 한다.
- **채점한 날 ≠ 푼 날.** 둘을 섞지 않는다. 보고서에 넣는 날은 선생님이 정한다(「물어볼 것」).

## 2026-11-27 교재

### 요청
- 학생마다 교재를 등록하고, vFlat 스캔본을 프린트와 똑같이 올린다.
- 채점된 스캔본은 분석해서 정답 · 오답 데이터를 쌓는다.
- 채점 안 된 스캔본은 분석해서 채점까지 하고, 교재별 문항 · 정답 데이터를 쌓는다.

### 고민
- 교재별 데이터(문항 · 정답)가 **없는 상태**에서, 프린트에 쓰던 기능을 최대한 똑같이 쓰기 위한 최선의 과정이다.
- 교재는 범위가 넓다. 프린트처럼 「2차에는 오답만 바로 보여 주기」는 하지 않는다.
  - 대신 **오답인데 채점이 마무리되지 않은 문항에 색 포스트잇**을 붙인다.
  - 나중에 **포스트잇이 붙은 것만** 볼 수 있게 한다.

### 정한 것
- 묶는 단위: **학생 × 교재 하나 = 채점 기록 하나**. 문항은 분석할 때마다 늘어난다.
- 분석: 「분석 맡기기」 묶음을 내보내 채팅에서 Claude가 분석 → 결과 파일을 가져온다.
- 1단계(PR #108): 등록 · 학생에게 붙이기 · 스캔본(1 · 2 · 3차 / 확실하지 않음, vFlat 공유). DB는 그대로(`tt_prints.options.textbook`).
- 기본값: 포스트잇 색은 1차 노랑 · 2차 주황 · 3차부터 빨강. 아직 화면은 없다(2단계).

## 2026-11-27 채점 표시 읽기 (스캔본 분석 — 2단계에서 씀)

### 선생님의 표시
| 표시 | 뜻 |
|---|---|
| ○ | 1차 맞음 |
| 빗금(/) | 1차 틀림(아직 다시 안 풂) |
| △ | 1차 틀림 → 2차 맞음 |
| X | 2차 틀림. 3차 스캔에서도 X면 3차 틀림 |
| 마주 보는 세모(리본 ⋈) | 2차 틀림 → 3차 맞음 |
| 표시 없음 | 채점 안 함 → 답이 있으면 Claude가 1차를 채점 |

### 안 푼 문제
- **체크(✓)만** → 「안 풂 — 넘어감」. 오답으로 세지 않고 포스트잇도 붙이지 않는다.
- **별표(★)나 빗금(/)** → 「안 풀었지만 오답」. 오답으로 세고 포스트잇을 붙인다.
- 어느 쪽인지 애매하면 「확인할 것」으로 보낸다.

### 선생님 채점을 다시 보기
- 선생님이 ○를 쳤는데 Claude가 보기에 **분명히 틀린 답**이면 「확인할 것」으로 보낸다. 선생님의 실수일 수 있다.
- **빨간 연필로 표시나 메모를 해 놓고 ○를 친 것**도 「확인할 것」으로 보낸다.
- 확인할 것마다 단추를 두 개 둔다.
  - 「내 실수 — 틀림으로 고치기」
  - 「맞다고 인정」 + **이유**. 이유는 바로 적거나, 「이유는 나중에」를 눌러 두었다가 「이유 몰아 적기」에서 한꺼번에 적는다.
- 이유에는 **선생님이 학생을 어떻게 바라보고 어떻게 가르치는지(교육관)**가 담긴다. 따로 모아 보고 내보낼 수 있게 한다.

## 2026-11-27 교재 분석 · 포스트잇 · 확인할 것 (PR: 교재 분석)

### 정한 것
- 새 표(Park 승인)

  - `tt_questions`: 물어볼 것(확인할 것 · 늦은 채점)과 답 · 이유
  - `tt_scans.analyzed_at`: 분석 결과를 넣은 때

  - 가이드에 채점 표시 읽기(위 표) · 안 푼 문제 · 선생님 채점 다시 보기 · 결과 모양을 적었다.
- **분석 결과 넣기**: 결과 JSON(코드 블록 · 앞뒤 글이 섞여도 읽음) → 미리 보기(새 문항 · 새 결과 · 바뀌는 결과 · 확인할 것 · 건너뛸 줄) → 넣기
  - 문항 · 결과 · 물어볼 것을 업무 기록 하나(여러 줄)로 남기고 한 번에 되돌린다. 그 뒤에 바뀐 줄이 있으면 통째로 되돌리지 않는다.
  - 선생님이 정한 정답(`teacher`)은 Claude 정답으로 덮지 않는다.
  - 채점한 날(`graded_days`)은 교재 기록(채점한 날)에 더한다.
- **포스트잇**: 지금 결과(가장 늦은 차)가 틀림인 문항. 색은 그 차(1차 노랑 · 2차 주황 · 3차부터 빨강). 「포스트잇만 · 모두」, 쪽으로 찾기, 그림 자리 보기.
  - 포스트잇 문항에서 바로 「다음 차 O · X」(오늘 · 선생님 채점) → 맞으면 포스트잇이 떨어진다. 되돌리기 있음.
- **물어볼 것**(`#/tt/ask`, 「오늘」 탭에 남은 개수)
  - 선생님 ○인데 틀림 · 빨간 표시 + ○: 「내 실수 — 틀림으로 고치기」 / 「맞다고 인정」 + 이유 / 「이유는 나중에」
  - 안 푼 문제 표시: 「넘어감(체크)」 / 「안 풀었지만 오답(별표 · 빗금)」
  - 애매한 표시: 후보(예: O · X) 중에서 고르기
  - 「이유 몰아 적기」, 「모은 이유」(JSON으로 받기 — 교육관 자료)
- 아직(다음 PR): 늦은 채점 질문(이유 · 어느 기록에 넣을지)과 `report_day`를 학습 기록 · 보고서에 쓰기, 프린트 스캔본 분석

## 2026-11-27 교재 기록 (PR: 교재 기록)

### 요청과 고민
1. **채점 날짜** — 문제 푼 날이 아니라 어디까지나 *채점한 날*.
   - 채점을 했는지 안 했는지 까먹었을 때를 대비한다.
2. **수업 끝 진도** — 수업이 끝날 때 어떤 학생이 어떤 교재를 몇 쪽까지 풀었는지 한 번에 적는다.
   - 나중에 Claude에게 「푼 것 중 채점 안 한 것」을 물을 수 있게 한다.
3. **데이터 뽑기** — 포스트잇 · 채점 기록으로 오답 쪽 · 푼 쪽 등을 뽑는다. 숙제를 낼 때 편하다.
4. **방치** — 교재 채점 기록을 기준으로 어떤 책을 얼마나 오래 그대로 두었는지 본다.
   - 해설지를 학생에게 주었는지도 적는다.

### 정한 것
- 새 표 `tt_book_logs`(Park 승인): `solved`(그날 몇 쪽까지) · `graded`(채점한 날 · 몇 차 · 쪽) · `solution`(해설지 준 날)
- 프린트의 채점한 날은 따로 적지 않는다. 매긴 시각(`tt_marks.at`)으로 차마다 보여 준다.
- 스캔본은 채점 안 한 것도 올리므로, 올린 것을 「채점한 날」로 치지 않는다. 그대로 둔 날수(마지막 채점)에는 넣는다.
- 기본값
  - 그대로 둔 날수: 14일부터 노랑, 30일부터 빨강
  - 진도 칸: 「45」(45쪽까지) 또는 「30-45」
  - 「채점 기록이 없는 쪽」: 진도로 푼 범위를 잡고 채점한 쪽을 빼서 어림한다. 채점한 쪽 기록이 하나도 없으면 어림하지 않는다.
- 오답 쪽(`wrong_pages`)은 스캔본 분석(2단계) 뒤에 채운다.

## 2026-11-27 업무 기록 · 되돌리기

### 요청과 고민
- 모든 입력 기능을 **강사 업무 기록**으로 남긴다.
  - 실수로 입력을 마쳤을 때 고칠 수 있어야 한다.
- 가장 직관적인 것은 **되돌리기 단추**다.

### 정한 것
- 입력마다 `tt_events`에 전 → 후를 남긴다(`detail.table` · `row_id` · `before` · `after`).
- 저장하면 알림에 「되돌리기」(8초). 지난 것은 「업무 기록」 탭(예전 「활동 로그」)에서 줄마다 「되돌리기」.
- 지금 모습이 그 기록의 「후」와 같을 때만 되돌린다. 그 뒤에 또 바뀌었으면 막고 화면에서 고치라고 안내한다.
- 되돌린 기록에는 `undone_by`를 달고, 되돌린 것도 새 기록으로 남긴다.
- 재원 · 원비 · 결석부 입력도 같은 방식으로 한다.

## 2026-11-27 물어볼 것 (계획)

### 요청과 고민
- 시간이 한참 지나서 채점 표시를 하지 않았던 문항을 채점하거나, 안 풀고 건너뛰었거나 오답인 채로 오래 둔 문항을 이제 처리하면 **선생님께 묻는다.**
  - 그때 잠정적으로 패스한 것인지
  - 그때 실수로 채점 기록을 무효로 했는지
  - 채점한 줄 알았는지
  - **가장 중요한 것**: 지금의 체크를 오늘 · 이번 주 학습 기록이나 이번 달 보고서에 넣을지, 넣지 않는다면 언제 기록으로 넘길지
- 자잘해 보이지만 굉장히 중요한 문제다.

### 정할 것(기본값 안)
- 「물어볼 것」 함 하나에 모은다: 늦은 채점 · 오래 둔 오답/안 풂 · 「확인할 것」(○인데 틀림 · 빨간 표시+○ · 안 푼 문제의 체크/별표) · 인정 이유(나중에 몰아 적기)
- 바로 답하거나 나중에 몰아서 답한다. 대시보드에 남은 개수를 보여 준다.
- 「오래」의 기준: 14일(설정에서 바꿈)
- 학습 기록 · 월 보고서는 답한 날짜로 센다. 실제로 채점한 날은 따로 그대로 둔다.
- 스캔본 분석(2단계)과 같이 만든다.

## 2026-11-27 재원 · 원비 (PR: 재원 · 원비)

### 정한 것
- 새 표 `tt_student_months`(Park 승인): 학생 · 달(그달 1일)마다 `status`(다님 attend · 휴원 pause · 그만둠 quit) · `fee`(그달 원비, 원) · 메모
- 화면: 학생 탭 「N월 재원 · 원비」(`#/tt/students/month[/YYYY-MM]`), 학생 화면 「재원 · 원비」 카드
  - 「안 적은 학생을 지난달과 같게」, 다님을 고르면 지난달 원비를 채워 줌, 고른 상태를 다시 누르면 비움(저장하면 그달 기록을 지움)
  - 원비 칸: 300000 · 300,000 · 30만 · 35만 5천
- 노랑 · 빨강
  - 이번 달을 안 적었고 지난달은 적었으면(또는 기록이 처음이면) **노랑**
  - 지난달도 비었으면 **빨강**(「10월부터 안 적음」)
  - 그만둠으로 끝난 학생, 기록 없이 쉬는 중으로 둔 옛 학생은 묻지 않는다(「그만둔 학생도 보기」로 볼 수 있음)
- 매출 = 그달 「다님」 학생 원비의 합. 달마다 12달 표, 원비를 안 적은 다님 학생 수도 보여 준다.
- 예전 「다니는 중 · 쉬는 중」 고르기는 없앴다. 이번 달까지의 마지막 재원 기록이 다님이면 다니는 중으로 저절로 맞춘다.
- 적을 때마다 업무 기록(전 → 후) · 되돌리기

## 2026-11-27 원비표 · 주당 횟수 (PR: 원비표)

### 요청과 고민
- 학원 블로그의 해마다 수강료를 미리 넣어 두고 싶다 → 블로그는 열 수 없어 Park이 표 사진을 보냈다.
- 수강료는 **학년 묶음 × 주당 횟수**로 정해지고, 해마다(2026년처럼) 바뀌거나 새 학년 묶음이 생긴다.
- 원비표는 학원 영업 정보라 **공개 저장소에는 금액을 적지 않는다** — DB의 원비표 표에만 둔다(시험도 가짜 값).

### 정한 것
- 새 표 `tt_fee_plans`(Park 승인): 언제부터(그달 1일) · 대상 이름 · 대상 학년(초1 ~ 고3) · 주당 횟수 · 수업 길이(분) · 월 원비.
  그달에 쓰는 원비표 = 그달까지 시작한 원비표 중 가장 늦은 것(그 원비표에 없는 학년은 그때 받지 않은 것).
- 재원 기록에 `per_week`(그달 주당 횟수)를 더했다.
- 재원 화면 · 학생 카드: 주2 · 주3(그달 원비표에 있는 횟수)을 고르면 **학생 학년 + 주당 횟수로 원비 칸을 채운다**.
  - 비어 있거나 방금 자동으로 채운 값일 때만 채운다 — 손으로 적은 원비는 건드리지 않는다.
  - 원비 칸 밑에 「원비표 중등 주3 …」를 보여 주고, 적은 원비가 원비표와 다르면 **「다름」**(할인 · 형제 등은 그대로 두고 눈으로만 알림).
  - 학년 글자를 못 읽으면(비었거나 「4학년」처럼 학교급이 없음) 원비표를 못 본다고 알린다.
- 「안 적은 학생을 지난달과 같게」: 상태 · 주당 횟수는 지난달 그대로. 원비는 지난달 원비가 **지난달 원비표대로**였으면 이번 달 원비표 값으로
  (원비표가 바뀐 달에 저절로 새 원비), 원비표와 달랐으면(할인 등) 지난달 원비 그대로. 3월에는 학년이 하나 올랐다고 보고 지난달 원비표 값을 견준다.
- 원비표 카드(재원 화면 아래): 원비표마다 「고치기」, 「새 원비표」(가장 늦은 원비표를 본떠 시작), 주당 횟수 칸 더하기 · 빼기, 원비표 지우기.
  원비표 한 벌 저장 = 업무 기록 한 줄(바뀐 칸들) · 되돌리기.
- 표나 칸이 아직 DB에 없으면 주당 횟수를 숨기고 안내만 한다(재원 · 원비는 그대로 적힘).

## 2026-11-27 푼 만큼만 매기고 넘어가기 (PR: 넘어가기)

### 요청과 고민
- 프린트를 낸 뒤 채점이 덜 된 상태에서, **푼 만큼만 채점하고 패스**하고 싶다. 문항이 많은 프린트이거나 학습 계획상 일부만 풀고 넘어가는 경우.
- 이미 있는 「아이가 덜 풀었어요」(남은 문항 = 안 풂, 나중에 이어서)와 다르다 — 넘긴 문항은 **풀어 올 것이 아니다**.
  그래서 안 풂(U)으로 두면 2차 다시 풀기 · 오답 프린트에 들어가 버린다 → 결과 종류를 하나 더 둔다.

### 정한 것
- 문항 결과에 **넘어감(P)** 을 더했다(`supabase/2026-11_tt_pass.sql`, Park 승인). 지금 결과가 넘어감인 문항은 2차 다시 풀기 · 오답 프린트 · 정답률에 넣지 않는다.
  나중에 풀어 오면 「1차 채점 수정」에서 O · X로 매기면 그 결과가 된다(기록은 쌓이고 가장 늦은 것이 지금 결과).
- 채점 화면 맨 위 「푼 만큼만 · 넘어가기」, 「채점 끝내기」 창의 선택지에도 같은 것.
  - 1차: 남은 문항(안 매긴 것 + 지난번 「아이가 덜 풀었어요」로 안 풂이 된 것)을 넘어감으로 두고 채점 완료.
  - 2차부터: 그 차에 아직 안 매긴 다시 풀 문항을 그 차에서 빼고 끝낸다(앞 차 결과가 그대로 최종). 그 차에 매긴 것이 없으면 넘기지 않고 「채점 취소」를 안내.
- 되돌리기: 알림 · 결과 화면 「넘어가기 되돌리기」 · 업무 기록. 넘기기 전 상태(채점 중 · 덜 풂 …)로 돌아간다. 그 뒤 채점을 다시 열었으면 되돌리지 않고 채점 화면에서 고치게 한다.
- 결과 화면 · 목록 · 보고서 · 분석용 내보내기에 「넘어감 n」. 학생 학습 기록 PDF의 「맞음/문항 수」는 넘어간 문항을 뺀 수로.

## 2026-11-27 풀어 줌 — 번호에 박스 (PR: 풀어 줌)

### 요청
- 수업 중 규칙: 프린트나 교재에서 **선생님이 풀어 준 문제는 문제 번호에 직사각형 박스**를 그린다.
- 알려 준 문제가 몇 개인지 따로 보여 주고, **맞은 문제로도 센다**.

### 정한 것
- 결과는 맞음(O) 그대로 두고 「풀어 줌」을 따로 적는다 — 정답률 · 다시 풀기 · 오답 · 반복 오답 셈은 맞음과 똑같다.
  - 프린트: `tt_marks.taught`(`supabase/2026-11_tt_taught.sql`, Park 승인). 매기는 함수는 결과 `T`를 「O + 풀어 줌」으로 받는다.
    채점 화면 「풀어 줌」 단추(단축키 B, 다시 누르면 지움), 「1차 채점 수정」에서도. 하위 문제 나누기 때도 따라감.
  - 교재: 표시 칸에 `box`(DB는 그대로). 분석 가이드에 박스 규칙 — 박스만 있으면 그 차 O(box), 다른 표시와 함께면 앞 차는 그 표시대로 · 박스는 그다음 차 O(box), 애매하면 물어봄.
    포스트잇 문항에 「풀어 줌」 단추.
- 요약 · 결과 화면 · 목록 · 채점 결과 PDF · 분석용 내보내기에 「풀어 줌 n」(O 가운데 몇 개).

## 2026-11-27 결석부 · 오늘 (PR: 결석부 · 오늘 대시보드)

### 요청과 고민
- 결석 확정 · 결석 예정 · 지각 예정 등 **불확실한 경우**를 적고 **사유**도 남긴다.
- **당일에 확인**하게 하고, 대시보드로 보여 준다.
- 나중에 **학부모 모드(종성)와 연동**한다: 학부모가 결석 여부와 사유를 간단히 넣으면 강사에게 저절로 전달된다.

### 정한 것
- 새 표 `tt_attendance`(Park 승인): 학생 · 날마다 하나
  - 종류 `kind`: 결석(absent) · 결석 예정(absent_maybe) · 지각(late) · 지각 예정(late_maybe) · 조퇴 예정(early_maybe) · 연락 없음(no_contact)
  - 사유 `reason`
  - 당일 확인 `checked`: 왔음(came) · 안 옴(absent) · 늦음(late). 다시 누르면 지운다.
  - 누가 넣었나 `source`: 강사(teacher) · 학부모(parent, 종성 연동용으로 처음부터 둠)

- **「오늘」 탭**(`#/tt/today[/날짜]`)을 맨 앞에 두고, 강사도구를 열면 여기부터 보인다.
  - 그날 결석부 + 적기
  - 확인 안 한 지난 결석부(예정 · 연락 없음으로 적고 그날 확인하지 않은 것)
  - 다가오는 7일
  - 재원을 안 적은 학생(이번 달) → 재원 · 원비 적기

  - 지난 30일 결석부
- 학생 화면에 「결석부」 카드(그 학생 것 · 바로 적기)
- 적기 · 확인 · 고치기 · 지우기마다 업무 기록(전 → 후) · 되돌리기
