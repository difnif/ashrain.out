# ASH RAIN. Out

수학은 매일. 개념 뷰어 · 질문-채택 루프 · 리브드 글라스 초상화를 담은 학습 앱.
(라이트 = 비 오는 거리 / 다크 = 재의 밤)

## 시작하기

```bash
npm install
cp .env.example .env      # Supabase 값 입력
npm run dev
```

### 1) Supabase
1. supabase.com 프로젝트 생성
2. SQL Editor에서 아래 4개 파일을 순서대로 전체 실행:
   `supabase/schema.sql` → `supabase/seed.sql` → `supabase/2026-07_profiles_extend.sql` → `supabase/2026-07_settings.sql`
   (이미 앞의 둘을 실행한 프로젝트라면 뒤의 둘만 실행)
3. Settings → API 에서 URL / anon key 복사 → `.env`

### 2) 첫 관리자
앱에서 회원가입 후, SQL Editor에서:
```sql
update public.profiles set role='admin' where id='<본인 uuid>';
-- uuid 확인: select id, name from public.profiles;
```

### 3) 초상화 기능 모델 (선택, 최초 1회)
```bash
npm install   # @mediapipe/tasks-vision 포함됨
cp -r node_modules/@mediapipe/tasks-vision/wasm public/models/wasm
```
`public/models/` 에 모델 2종 다운로드:
- https://storage.googleapis.com/mediapipe-models/face_detector/blaze_face_short_range/float16/latest/blaze_face_short_range.tflite
- https://storage.googleapis.com/mediapipe-models/image_segmenter/selfie_segmenter/float16/latest/selfie_segmenter.tflite

### 4) 라이트 테마 배경 사진 (선택)
`public/brand/rainy_street.jpg` 를 넣고 `src/components/SplashAuth.jsx`의
`.th-light` 블록 주석에 표시된 한 줄을 교체.

### 우물 — 메인 테마 (2026-09-20)
하단 탭바 중앙의 원형 「우물」. 탭 4개는 납작하게 좌우 2+2로 벌리고 가운데에 우물이 탭바보다 크게 얹힌다.
그림은 **기본 1장** — 번들 `public/brand/well/base.webp`(템페라 화풍 돌우물, 원형 메달 컷)이 기본이고,
관리자가 스토리지 `figures/well/base.*` 업로드로 교체할 수 있다(지우면 번들로 복귀).
연출은 **3가지**(확정): 맑은 낮 = 태양 각도(`src/lib/sun.js`) 그림자가 실시간으로 돈다(방향 센서 기기는 나침반 연동 —
iOS 는 첫 탭에서 권한 1회, 안 되면 화면 위=북 고정) · 흐리거나 비·눈 = 그림자 없이 감광 · 밤(20~6시) = 중앙 조명 연출.
실황은 대시보드 히어로와 같은 신호(`src/lib/wx.js`), 상태 결정은 `src/lib/well.js`(wellMode).
우물을 탭하면 사진 도구 런처(학습 도구와 동일 5종: 서술형 채점·첨삭/사진 힌트/문장 해설/표시 연습/풀이과정 검사).
크기·이미지는 `#/admin/well` — 미리보기의 우물을 직접 눌러 편집 모드(탭바 높이·탭 크기·우물 지름·튀어나옴·이미지 배율·오프셋),
저장은 `app_settings.well_ui`(전 학생 즉시 적용). 촬영모듈은 학습 도구의 「찍어서 배우기」 타일로도 들어간다.

### 공부하기 — 빠른 목록 · 개념 검색 (2026-09-21)
**느렸던 원인**: 개념 공부·연습문제가 들어갈 때마다 단원 12개 × 개념 N개의 count 질의를 따로 날렸다(30+ 왕복).
**지금**(`src/lib/studyCache.js`): 문항 수는 `(unit_id, concept_ids)`만 받는 **한 번의 질의**로 클라에서 세고(`tallyCounts`),
개념 목록과 함께 메모리+sessionStorage 에 10분 SWR 캐시 — 재방문은 왕복 0회, 첫 방문도 셸이 1.8초 뒤 미리 데워 둔다
(`warmStudy`: 화면 청크 + 데이터). 필터(qtypes·withRubric 등)별로 캐시 키가 나뉘므로 수는 항상 정확하다.
관리자 문항 등록 뒤에는 `bustStudyCache()`.

**개념 검색**(`src/lib/koSearch.js`) — 개념 공부·연습문제·시험 범위 고르기(ItemPicker 공용) 상단에 검색칸.
이름·부제·학기명을 공백 무시 부분일치로, 질의가 전부 초성이면 초성열(ㅈㅅ→정수와 유리수)로 찾는다. 학기 무관 전체에서 최대 30건.

**칩 간소화** — 학기 칩은 내용(문항·개념)이 있는 학기만 기본 노출, 나머지는 「다른 학기 +N」으로 접어 둔다
(개념 공부·연습문제·단원 테스트 범위 공통). 새 학기는 문항이 등록되면 자동으로 칩이 드러난다.

### 촬영 판독 — 백그라운드 잡 · 수율 폴백 · 필기 지도 (2026-09-21)
**백그라운드 판독**(`src/lib/photoJobs.js`) — 채점·판독·검사는 화면이 아니라 앱 전역 잡으로 돈다. 판독 중에는
「🏠 자리 비우기」·「판독 취소」 버튼(`JobBusy`)이 뜨고, 뒤로가기·다른 탭에 다녀와도 작업은 계속된다. 끝나면
토스트 + 기록 탭 뱃지(진행 중 ●펄스 / 새 결과 ●) + (허용 시) 브라우저 알림. 결과는 잡 안에서 기기 보관소에 저장되고
진행 중 잡은 기록 탭 상단 스트립에도 보인다. **브라우저 창을 완전히 닫으면 중단**(사진·답안 서버 무저장 원칙 때문 —
서버 큐는 TWA 때 재논의). 취소해도 이미 쓴 사용 횟수는 차감.

**모델 3키**(`app_settings`) — `photo_model`(전사 1차·기본 sonnet) · `photo_model_grade`(채점·첨삭·검사) ·
`photo_model_fallback`(전사 재시도, 없으면 grade 모델). 클라(`scanCall`)가 1차 전사를 못 읽었거나 수식 경고가 남으면
`retry_strong:true` 로 강한 모델 1회 재시도 후 더 나은 쪽을 쓴다(한도 1회 추가 차감 — 60초 함수 예산 안에서 안전).

**필기 습관 지도**(`src/lib/hw.js` + `HwGuide`/`HwMarks`) — 답안 스캔이 학생 책임 필기 문제
(messy·faint·scribble·two_column)를 위치 비율 box 와 함께 보고하면, 전사 화면에서 **사진 위 형광펜** + 번호 + 지도 문구로
짚어 준다(두 단 정렬이면 "한 단 서술, 부득이하면 단 사이 화살표" 종용). 답안 촬영 단계 진입 시 **필기 약속 팝업**
(또박또박·진하게·한 줄기·두 단이면 화살표)이 기본 노출 — 「한 달 동안 보지 않기」 가능, 단 필기 오류가 **5회 누적**되면
숨김 중에도 다시 띄우고 확인하면 리셋(카운트·숨김 모두 기기별 localStorage). 학생이 전사를 고쳐 채점받으면
원문(`answer_raw`)도 기기 기록에 남는다(오독 패턴 개선용, 서버 전송 없음).

### 교실 모니터 — 수업 장면(도형 · 경우의 수·확률) + 액자(하노이의 탑 · 실험 셋 · 장면 묶음 둘 · 3D 축구) (`#/admin/display`, 2026-10-26 · 10-29 · 10-30)

**수업 장면**은 교육과정에 맞춘 도형 · 경우의 수·확률 애니메이션 17쌍이 자막·판서와 함께 자동으로 돈다.
교육과정에 딱 맞기보다 융합·탐구에 가까운 것(축구 · 서술형 · 몬티홀 · 갈림길과 구슬 · 갈톤 보드)은 수업 장면 순환에서 빼고 **액자**로 켜 둔다.
오른쪽 위 **초등 | 중등** 토글 — 두 판이 같은 박자표로 저작되어 있어서, 누르면 지금 장면이 같은 순간의 짝 장면으로 겹쳐 넘어간다(액자도 같다).

조작: 화면을 누르거나 움직이면 위 가운데에 조작 막대(이전·멈춤·다음·이 장면 반복·목록·밝기·전체 화면·나가기)가 뜨고 3.6초 뒤 숨는다. 키보드 ←/→ 장면, 스페이스 멈춤, T 학년 전환(E 초등·M 중등), F 전체 화면, L 목록.
돌릴 묶음: 목록 위 칩(전체 17 · 도형 12 · 경우의 수·확률 5)으로 고르면 자동 순환·←/→가 그 묶음 안에서만 돈다. 「이 장면 반복」을 켜면 지금 장면 하나만 되풀이한다.
켜 두는 동안 화면 꺼짐 방지(Wake Lock). 학년·밝기·마지막 장면·묶음·장면 설정·켜 둔 액자는 기기에 기억한다.
⚙ 장면 설정: 장면이 `controls` 를 가지면 조작 막대가 뜰 때 그 아래에 설정 칩(− 값 +)이 함께 뜬다. 바꾸면 그 장면을 처음부터 다시 틀고, 장면마다 기기에 기억한다. ↑/↓ 키는 첫 설정을 바꾼다.

**액자** — 오른쪽 위 학년 토글 왼쪽의 액자 단추 → 액자 목록(그림 · 실험 · 장면 묶음, 3칸) → 고르면 수업 장면 대신 그 액자가 쉬지 않고 돈다(수업 장면 시계는 그동안 멈춰 두었다가 돌아오면 이어진다). 액자는 벽시계로 흘러서 새로고침해도 이어진다.
- 「하노이의 탑」: 원판 3~20개(처음 14개). 다 옮기면 4초 쉬고 거꾸로(C → A), 또 쉬고 A → C … 끝없이.
  - **빠르게** = 1초에 1개 → 다 옮기는 시간 정확히 (2ⁿ − 1)초 (13개 2시간 16분 31초 · 14개 4시간 33분 3초).
  - **자연스럽게** = 이동마다 원판이 실제로 지나가는 길(들어 올림 + 건너감 + 내려놓음) 길이에 비례(1초에 780px, 평균 1.8초쯤). 천천히 출발해 사뿐히 내려놓는다.
  - 조작 막대: 처음부터 · 멈춤 · 원판 −/+ · 자연스럽게|빠르게 · 밝기 · 전체 화면 · 액자 목록 · 수업 장면으로. 막대 밑에 두 빠르기의 다 옮기는 시간이 함께 뜬다. 키보드 스페이스 · ↑/↓ · S · R · F.
  - 아래 안내: 원판 수 · 방향 · 「16,383번 중 3,021번째 · 남은 시간」. 빠르기를 바꾸면 지금 옮기던 그 이동에서 이어지고, 원판 수를 바꾸면 처음부터.
  - 검산: `node tests/hanoi.test.mjs` — 모든 이동을 기둥 셋으로 따로 흉내 내 규칙·최소 횟수(2ⁿ − 1)·닫힌 식과 맞추고, 빠르게 = (2ⁿ − 1)초, 자연스럽게 = 이동 시간 ∝ 길이, 길이 기둥 끝을 넘어서만 옆으로 가는지, 원판 3·7·14·20을 두 빠르기·두 테마로 끝까지 그려 본다.
- **실험 액자** 셋 — 하노이의 탑처럼 경우의 복잡도를 높이는 수를 마음대로 바꿔 가며 **직접 해 보는 것이 먼저**이고, 확률 풀이는 실험 사이사이에 판 곁의 짧은 글 · 막대 · 자막으로 끼어든다.
  조작 막대: 처음부터 · 멈춤 · 밝기 · 전체 화면 · **해 보기 | 풀이 보기** · 수업 장면으로(키보드 V 로도 바꾼다), 그 아래 설정 줄. 「풀이 보기」는 예전 설명 장면을 그대로 돌린다(그 장면을 처음부터).
  - 「몬티홀 — 바꿀까, 그대로 둘까?」: 문 3~10개 · 사회자가 여는 문 0~n−2개 · 사회자가 답을 **알아요/몰라요** · **직접/저절로** · (저절로) 자연스럽게|빠르게.
    - 직접: 반 아이들이 문을 눌러(키보드 1~9 · 0) 고르고, 사회자가 문을 연 뒤 그대로/바꾸기도 눌러 정한다. 「우리 반 기록」이 설정마다 기기에 쌓인다(처음부터 = 기록 지우기).
    - 저절로: 컴퓨터가 한 바퀴(자연스럽게 30판 · 빠르게 300판)를 하며 판마다 그대로·바꾸기를 함께 세고, 이긴 비율 막대가 이론값(점선)으로 다가간다. 바퀴 끝에 정리.
    - 문 아래 막대(그 문 뒤에 자동차가 있을 확률)가 사회자가 연 문에서 닫힌 다른 문으로 옮겨 가고, 한 줄 풀이가 「내 문 {1/n} · 고르지 않은 문 모두 {(n−1)/n}」→「닫힌 다른 문 하나에 (n−1)/(n(n−1−k))」를 말한다. 모르는 사회자가 자동차를 열면 그 판은 세지 않는다 → 닫힌 문은 모두 1/(n−k).
    - 풀이 보기: 바꿀까, 그대로 둘까?(문 3~5개⚙) · 다섯 개 중에서 고르기(5지선다 찍기) · 이어진 문제 함께 고르기(맞물린 답).
  - 「갈림길과 구슬 — 하나씩, 한꺼번에」: 단계 1~4 · 구슬 2~6개. 한 바퀴 = ① 주머니에 담기 ② **하나씩**(주머니 아래가 풀려 한 개씩) ③ 다시 담기 ④ **한꺼번에**(주머니가 터져 우르르, 부딪힌 곳에 번쩍) ⑤ 300판씩 모아 비교(모양별 비율 · 이론값 · 판정). 주머니를 누르면(Enter) 바로 떨어뜨린다. 판 아래에 구멍마다 길의 수(초등) · 확률(중등), 오른쪽에 이번 바퀴의 두 결과.
    - 풀이 보기: 두 갈래 길과 가능성 · 갈림길이 늘어나면(단계 2~6⚙) · 구슬이 부딪히면?(단계 1~3 · 구슬 2~4개⚙).
  - 「구슬 낙하 실험 — 갈톤 보드」: 못 6~12줄 · 구슬 100~2000개. 한 바퀴 = 준비(못이 한 줄씩 박히며 파스칼의 수, 통에 구슬) → 낙하(첫 구슬을 금빛 자취로 따라가 「오른쪽으로 k번 → 칸 k」) → 정리(칸 아래 실제 개수, 초등 꺾은선 · 중등 기대 개수와 정규분포 곡선, 가운데 칸 C(R, R/2)/2^R). 판을 누르면 바로 떨어뜨린다. 바퀴마다 결과가 조금씩 다르다.
    - 풀이 보기: 구슬 낙하 실험(구슬 100~2000개 · 못 6~12줄⚙).

  - **⚽ 3D 축구** (2026-10-30) — 축구 여섯 장면에만 오른쪽 위에 **2D | 3D** 토글(키보드 3)이 뜬다. 3D 를 켜면 위에서 내려다본 그림 대신
    경기장 속 **사람 눈높이**에서 그 장면이 시뮬레이션으로 돈다(화면 전체 — 16:9 무대 바깥 여백까지). 더 지니어스의 규칙 설명 그림처럼

      그려지고, 큰 글씨 설명이 왼쪽 반을 채운다(주인공 선수 · 공만 밝게 남는다). 설명이 끝나면 다시 눈높이로 내려와 이어진다. 골 · 다시 보기 · 정리.

    - 3D 판은 박자표가 따로라 켜고 끌 때 그 장면을 처음부터 튼다. 기기에 기억한다. three.js(WebGL)는 3D 를 처음 켤 때만 내려받는다(따로 나뉜 파일).
      WebGL 을 못 쓰는 기기면 2D 로 돌아오고 잠깐 알린다. 느린 기기에서는 그리는 해상도를 스스로 낮춘다. 밝기 토글 = 밤 경기 · 낮 경기.
